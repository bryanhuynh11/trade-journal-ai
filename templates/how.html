How it works

One model call per trade note. Everything before and after it is plain Python you can read and test.

1
Import CSV CODE

tj/parse.py reads the Tradovate Performance export, sorts trades by entry time, works out long/short, and parses $(22.50) as −22.50.

↓
2
Facts & rule checks CODE

tj/facts.py computes the killzone, hold time and R-multiple, and checks your limits in tj/rules.py: outside killzone, oversized, too many trades, past the daily loss limit. These become rule: flags. They're things the numbers prove, so the model never decides them.

↓
3
You write notes YOU

What you saw, why you entered, how you felt. Messy is fine. This is the part code can't read.

↓
4
Claude labels the note MODEL

tj/tagger.py runs claude -p --tools "" headless (no file or shell access) with the facts and your note. It must reply with one JSON object: setup, mistakes, emotion, followed_plan, an exact quote as evidence, a lesson, and confidence. It runs on your Claude Code login, not a paid API key.

↓
5
Validate → retry → or UNTAGGED CODE

tj/schema.py checks every field. If anything fails, the errors go back to Claude for one retry. If it fails again, the trade is marked UNTAGGED rather than trusted. Valid answers are cached, so re-runs are instant and cost nothing.

↓
6
Stats & report CODE

tj/report.py groups P&L by setup, killzone, issue and emotion. The model never does math.

Debugging: whose fault is it?

A wrong rule: flag or a wrong number → bug in Python (facts.py / rules.py).

A wrong note: tag or setup → the model misread your note. Open "See exactly what Claude was sent" on the trade, check the quote it used, and fix the prompt or the allowed lists.

A trade marked failed → the model couldn't produce valid JSON twice in a row. The validator's reasons are shown on the trade.
